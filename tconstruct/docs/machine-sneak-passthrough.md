# Sneaking at Faucets and Casting blocks

Pinned TConstruct `f4e77d43` [FaucetBlock.use](https://github.com/SlimeKnights/TinkersConstruct/blob/f4e77d43f39ba1047bf93ae816b7e1beaab514c2/src/main/java/slimeknights/tconstruct/smeltery/block/FaucetBlock.java) and [AbstractCastingBlock.use](https://github.com/SlimeKnights/TinkersConstruct/blob/f4e77d43f39ba1047bf93ae816b7e1beaab514c2/src/main/java/slimeknights/tconstruct/smeltery/block/AbstractCastingBlock.java) return PASS whenever the player is sneaking, including with empty hands.

The authoritative machine-use adapter now preserves that behavior for Seared/Scorched Faucets, Casting Tables and Casting Basins. Empty-handed sneaking no longer starts a pour or exchanges casting contents. Normal interaction remains unchanged. The existing bypass while sneaking with either hand occupied remains in place for every block, allowing the held item to continue its ordinary use/placement path. Other empty-handed machine controls are unchanged.

This uses the existing ShiftLeft state in the host action context. Remote clients still bypass this adapter and delegate to their host. The pinned host's guest action context swaps the guest's selected inventory and offhand into the operation and sets ShiftLeft from that guest's sneak state, not from the host player's keys. A conditional source-wiring test checks those exact pinned-host statements when HORIZON_HOST is provided. That is static verification, not a live LAN test.

Run `HORIZON_HOST=/path/to/pinned/horizon python3 -m unittest discover -s tconstruct/tests -p test_machine_sneak_passthrough.py -v` with rustc available. Production policy tests cover both source block families, all main/offhand combinations, sneaking versus normal use and unaffected control blocks. Wiring checks place the early return before fluid/item operations and animation, and retain remote delegation. Full Game dispatch, actual offhand placement, input remapping, GUI, saved state and LAN gameplay remain unverified. Faucet timing/redstone, casting redstone and other fluid-handler parity are unchanged.
