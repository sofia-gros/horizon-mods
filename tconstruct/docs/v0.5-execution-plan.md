# v0.5 実行計画（レビュー用・未承認）

最終目標は原作 Tinkers' Construct 1.20.1 [`f4e77d43…`](https://github.com/SlimeKnights/TinkersConstruct/tree/f4e77d43f39ba1047bf93ae816b7e1beaab514c2) の完全移植。v0.5 はその途中の、自力で遊べる先行版である。現在の [roadmap](roadmap.md) は「原作の大部分」と定義し、全機能完成を主張していない。この文書は作業の順序と証拠を管理する提案であり、未決の機能を無断で削る承認ではない。計画のユーザー報告前に、ここに追加した新規機能へ着手しない。進行中の修正・テストは継続する。

## v0.5 の完了条件と範囲

**確定したゲート：** 公式の現行 Horizon／Mixins を使用し、Mod 本体と PlutoLib を同じ固定 pair で stage／build。原作ソースと登録データを基準に、素材取得→部品加工→工具組立→使用・損耗→修理・強化、設備制作→溶解→鋳造の主要導線が成立する。保存・再読込、材料・結果の個数と component、vanilla への回帰、代表 LAN と Linux 起動を確認する。既存 roadmap は Windows 起動確認も公開条件に挙げているが実機未確認で、Windows 配布対象・確認範囲は U5 で明確化する。対象 PR は exact head で検証・独立レビューし、必要 checks を満たして main へ通常 merge。README／各機能 docs はその時点の導入・対応版・実測／未実測と一致する。最終的な survival 通しプレイはユーザー本人が行う意向なので、実行手順と成果物を提供し、代理実施済みとは記載しない。

**v0.5 の機能範囲として roadmap に挙がる作業：** 材料 traits、工具・武器・防具固有動作、Station／Anvil・modifier・部品、製錬／鋳造／容器／残ブロック、自然入手・slime world・生物、ガイド／進行／残コンテンツ。各グループは下記タスクと source matrix を対応させる。既に動作する機能を一律に作り直さず、未実装や不一致から着手する。

**暫定的にピンポイント停止中：** Reinforced／Unbreakable 適用と Dense 等の損耗防止、防具の動的 wear／Overslime 書戻し、素材付き収納の world face／connected glass／Chest tint、Excavator／Battlesign knockback、Crafting Station の recipe-book 配置（#88 修正待ち）。Crumbling＋Stonebound は不一致を調査中。個々の機能を停止しても item／画面全体を消さない。LAN 側だけが未完成でも安全に独立する SP を止めない。**これらを v0.5 リリースで保留できるという承認はまだない。** 原作差・影響・原因・代替／復旧条件をそれぞれ示し、未決のまま完了と数えない。

**対象外と明示されたもの：** 広範な異種 Mod 互換性試験、Java Mod 互換、独自 loader／host fork／新 protocol、PlutoLib の汎用 API 全網羅。現行 vanilla と共存し、本 Mod 自身の保存・同期・個数を守ることは対象内。自然採取からのユーザー自身の通しはユーザー担当。完全一致と balance の全確認は v0.5 後も続くが、原作の代わりに独自挙動を完成扱いにしない。

**決定待ち U1–U5：** U1 原作「大部分」の具体的な内容表と、各残件を v0.5 必須か後続か決める権限・基準。U2 上記停止 hook を公開版で許容するか、各機能別に決める。U3 slime islands／固有 fluids・state・tree・生物の v0.5 必須範囲。U4 全 modifier／装備固有動作／残りの本・実績・automation の最低内容。U5 Windows とスマホの成果物・実機範囲および LAN／専用サーバーで公開時に主張する範囲。テスト未実施を「不要」とはしない。決定待ちの件数が 0 になり、対象の機能台帳が揃うまで確実な ETA・全体達成率は出さない。

## 実行方法と完了定義

6 roles：**W** 作業台／鋳造・Smeltery、**M** 素材／装備・進行、**G** guide／world 表示、**P** PlutoLib／公式 host 接続、**T** テスト専任、**R** 独立レビュー・merge。担当名は稼働中 session に対応付け、同一ブランチの writer は一人。計画・進捗・shared root 文言は PM が管理。各 role は依存が満たされた上から着手し、2–5 件を先行キューに保持。テスト渋滞時は PM が空き role をテスト・レビューへ段階再配分し、毎 PR で往復させない。全員 Terra medium。最新 pair を取り込む PR は一本化し、test も #103 の更新後 tree を対象とする。

開発 role は原作と既存実装を照合して実装、Rust 構文と diff を確認し PR へ正確な未検証を記す。T が複数機能をまとめて正式変換・型・unit・Linux game・画像・代表 LAN を行い、製品 head／統合 tree・fixture・モードを記録する。R は既存証拠を再利用して重大差分・データ消失／増殖・権限・docs を確認、exact head と base を確認して通常 merge。Approve／保護回避・無断 force push はしない。失敗時は最小再現・影響・固定 SHA を担当へ戻す。LAN のみ失敗時は SP の独立性を評価。元ソースと同等な安全な接続がない場合は該当操作のみ停止して U2–U5 に記録する。共通スロット planner は採用済み、汎用 batch transaction や新 framework は前提にしない。

表中の「完了」は **実装→T の指定試験→R の確認→main** を指す。行末「次／阻害時」は成功後に進む先と、詰まった場合に同時進行できる先であり、失敗を合格扱いする意味ではない。各行の既存テスト名は提案であり、この文書作成時点の実施結果ではない。

## PR 依存と現在のゲート

棚卸し時点の PR は構文中心・実ゲーム待ちが多い。次の図は依存関係であり合格の宣言ではない。矢印は親の受入・main 反映を先に行うことを表す。統合 test は機能群をまとめて実施可能だが、各 PR について試験済み source との差分を照合する。

```text
#103 latest pair ──> T01 ──> 各機能群の統合試験
#82 ──> #98 ──> #101
#81 (merged) ──> #83 ──> #86 ──> #91 ──> #96
                                  └──> #102 (base #91)
#93 ──> #97 ──> #99 ──> #104
#94 ──> #95 ──> #100
#85 / #87 / #90（各独立、book 同一ファイル競合に注意）
#88（BE 消失の事前拒否修正を静的確認、実機待ち）
#92（Venom 容器、実機待ち）
#54（slime island、生成停止・不足機構あり、U3）
```

#79／#81／#84／#89 は main 統合済み。PR #99 の component 付き bucket はコードが保持する方針に説明更新済みだが、保存までの証拠は未取得。各 PR の exact head・checks・試験・競合・変更点を main 統合前に再確認し、依存先の main 取り込みに伴う重複差分を解消する。PR が draft／open のままでも次の実装を無制限に積まず、テスト対象 batch とレビュー結果を先に確定する。

## 進捗台帳・公開ゲート

- この計画の **確定した作業単位の分母は 30 行**（W/M/G/P/T/R 各 5）。各行に `未着手 / 進行中 / 検証待ち / レビュー待ち / main 完了 / 該当操作のみ保留`、owner、head、証拠 URL、blocked reason と次回確認点を記録する。各 role の行は検証と統合を含むので、同じ PR を別の完了機能として足し合わせない。初回の状態は未棚卸しであり、0/30 完了と推測しない。
- **検証母数は作業 30 行と別管理：** V1 最新 pair の正式変換・型、V2 作業台／鋳造と個数保存、V3 工具／素材・装備、V4 guide／world／自然入手、V5 保存・再開と代表 LAN、V6 Linux 起動と配布、V7 Windows 起動・配布範囲（U5 に依存）。各 V は exact SHA・手順・結果・適用範囲を記録し、対応する必須シナリオが出揃うまで pass にしない。ユーザー自身の survival は別の user-validation として受領／未受領を管理し、内部で代行したことにしない。V1–V7 はカテゴリ数であり、未定義シナリオを網羅したという主張ではない。
- 30 行は運用単位であり原作機能の母数ではない。U1–U5 が残る間に行を分割・追加したら分母と理由を履歴に記録し、変更前後の割合を直接比較しない。原作 source matrix の各行に `source / 実装・未実装 / 保存・取引 / 代表実測 / 未検証 / v0.5 判断` を別途維持し、登録数で完成率を作らない。
- 計測は対象期間の **merge 済み feature units、同一 SHA でのテスト完了、open blocking 件数、待機時間** を UTC で記録。画像や fixture を成功の範囲以上に使わず、コミット数・PR 数だけで速度を判定しない。各 role の 2–5 件キューと blocked 数を PM が点検する。
- リリース候補では source／package／Horizon／Mixins の full SHA、起動手順、必要資源、PR 別試験、SP／LAN／Windows／mobile の実施・未実施、意図的停止、既知の損失リスク、ユーザーが実施する survival 手順を対応付ける。未解決の損失／増殖や、許容の決まっていない停止はゲート未達。docs 全面改定は移行完了後とし、各 PR の関連 docs は常に同期する。
