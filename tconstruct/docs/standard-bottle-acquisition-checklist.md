# Standard bottle and splashing acquisition: verification input

Static cross-check against TConstruct 1.20.1 generated data and candidate #323 (`451985fd9fe786d8f2747cfee33101d759ade551`). This is an acceptance checklist, not a package, apply or gameplay result. The normal pack, without fixture tags or inventory injection, must provide the inputs for a natural-acquisition test; retain separate diagnostics when a world fixture is necessary.

| Operation | Original data / candidate entry point | Expected checks |
| --- | --- | --- |
| Splash and lingering empty bottles | Original `forge:bottles/splash` contains `tconstruct:splash_bottle`; `forge:bottles/lingering` contains `tconstruct:lingering_bottle`. #308/#313 register both; `source-splash-bottle-brewing.rs` derives reagents from loaded potion-container mixes. | With ordinary vanilla mixes, glass bottle + gunpowder yields the splash bottle, then splash bottle + dragon breath yields the lingering bottle. Preserve the normal stand's counts and reagent/container handling. An existing conflicting recipe must not be shadowed; reload must not duplicate the candidate mix. Test the exact host loader and stand. |
| Standard splashing modifier | Upstream `tools/modifiers/ability/splashing.json`: two `forge:bottles/splash`, one `tconstruct:no_container` / `tconstruct:tanks`, two `forge:ingots/copper`, one ability slot, durability and interactable intersection. #323 planner checks stack-sensitive `no_crafting_remainder` and limits supported tools to the four staffs and melting pan. | Natural empty splash bottles and empty supported tank select the recipe on a supported built tool; one missing bottle, filled tank, malformed tank data, missing copper, full ability slots and unsupported tool do not consume inputs. Check output data and inventory counts, close/reopen and LAN. This restricted supported set is not all original tools. |
| Water container usage | `source-empty-bottle-use.rs` and `source-bottle-cauldron.rs` implement source/waterlogged and cauldron paths. | Empty bottle used at permitted water yields its corresponding water potion; water cauldron levels decrease when filled and increase when a water potion is emptied, with matching empty bottle. Check stacks, full inventory, survival/creative, protected sources, levels 0 and 3, non-water potions, close/save, and local/LAN owner and guest separately. |
| Casting water | Original `smeltery/casting/water/splash.json` and `water/lingering.json`: matching empty bottle is consumed with **500 mB** `mantle:water`, cooling time 1, producing the corresponding water potion. | Exact input bottle, fluid amount, potion data, output capacity, insufficient water and reload conservation in the real casting table. Do not substitute the potion-fluid casting quantity below. |
| Casting potion fluid | Original `smeltery/casting/filling/lingering_bottle.json` selects a splash bottle and yields a splash potion; `filling/splash_bottle.json` selects a lingering bottle and yields a lingering potion. The source filenames are counterintuitive; use their JSON contents. | Check bottle tag, potion identity and supported tagged/custom effects; reject unsupported LAN metadata operations as documented and verify exact fluid and item counts. |
| Melting empty bottles | Original `smeltery/melting/glass/bottle.json` accepts glass bottle and both bottle tags, yielding **1,000 mB molten glass**, temperature 750, time 73. | Verify each item via normal packaged tags, temperature and output capacity; no selection for unrelated items and no material loss on failed transactions. |

The original generated recipe values above do not establish that the integrated host currently exposes every item or executes every route. In particular, the brewing interception and casting, crafting and world interaction hooks require formal apply/type/game validation against the selected exact Horizon and Mixins revisions. The #323 integration also needs a combined check that adding speedy/step-up and gilded did not alter splashing's one-ability-slot accounting.
