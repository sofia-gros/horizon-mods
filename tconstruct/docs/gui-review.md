# Existing-screen GUI checklist

The reference is the fixed Tinkers' Construct source and its original assets. These checks describe the implemented screens; representative checks are not a claim of pixel-perfect parity in every state or language.

Only Part Builder and Tinker Station tabs currently open implemented workstation menus; other registered workstations have no corresponding GUI and are shown as unavailable. Unsupported machine recipes, modifiers and blocks are not implied by the GUI. Large multi-viewer combinations, every item/material, all languages and Windows have not been individually verified.

## Resume: Station armor preview

PR #25 remains a draft; do not treat armor preview as complete. The tested runtime is `ed01ffd` (Mixins `4342a0bfbe71d4d14185528d64e496d6022f16a1`); the subsequent commits through `4503da8` add screenshots and documentation. The apparent floating Plate Helmet needs a material-equipment rendering path: generated `items.json` for `tconstruct:plate_helmet` has `minecraft:equippable.slot=head` but no `asset_id`, so the preview finds no `equip_asset` and draws no helmet layer. A follow-up check using an iron helmet with the same Station operation metadata rendered a complete helmet over the stand's head. The source-derived `armor_stand#main` and `armor_stand#helmet` models have the same head pivot `(0, 1, 0)`; their head bounds overlap, and the preview uses the same base and pose logic as Horizon's world renderer. Do not move the common head transform based on the Plate Helmet screenshot. Determine the original TConstruct material armor texture/model resolution and connect the real material-dependent asset; do not claim a generic iron replacement is original parity. Compare an actual original-game reference if available.

The current fixed test world and cache remain under `target/pb-station-batch`, `target/build`, and `target/integration-batch-stage`. ### Partial steel preview follow-up

Commit `dd23eed` adds a first, unverified connection for a Plate Helmet whose plating and maille are both `tconstruct:steel`: the two original generated 64×32 PNGs are staged in the HUD atlas and used with Horizon's existing armor-stand geometry and pose. Their SHA-256 hashes match fixed source revision `f4e77d43`; Python syntax and 43 Python tests passed. This is an initial hard-coded representative, not a complete material resolver: other materials, slots, dye, fallback selection, trims and the visual compositing/depth of the two layers remain unimplemented or unverified. The Rust change has not passed official Mixins transformation, type checking or game testing. Existing verified runtime remains `ed01ffd`. Next, inspect and test layer blending in the real HUD, implement source material/fallback resolution across matching source sprites, and check the representative steel helmet in-game before claiming this issue is fixed. No build or CI was started for `dd23eed`.

Both layers must exist or neither is drawn. A representative steel/cobalt snapshot test and the Python suite passed (44 tests). This is still a partial, unverified renderer: material variants, render-info fallbacks and tint, dyed modifiers, trims, other equipment and alpha/depth compositing require further work. In particular the exact-texture-only lookup must not be treated as the full original material resolution. No official transformation, Rust type check, game validation or CI has been run on this follow-up. Preserve world/cache; the tested runtime remains `ed01ffd`.
