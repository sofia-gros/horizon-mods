## Current main and bundled ingredient audit

Main `61613253e4aa06eb2e739a9f6343a93652f014f8` includes merged #217; its supplied-material Linux fixture covered ordinary planks, Blazewood, Nahuatl, mixed and failure cases, plus a LAN guest crafting with Nahuatl. Final-main package integration, Windows, LAN restart and source retexturing remain distinct checks. This branch reconciles main into the later workstation candidate without changing the previous fixed heads.

The test owner reports official apply and Linux build success for #214 head `506d43661b5cb581736e94ae4d5e3a590d6a51b3` in integrated tree `e3bd01cb5e6c94c29d0ffb3095fcf4851d1dcbd3`, with temporary version-pin edits and its matching Pluto bundle, using Horizon `b53cfcd14eab7b6ed2fe91a3a3773d7415402ab9` and Mixins `ddd9700b21997c95d95ac6ee5ecafe3830cf622a`. This does not establish build or runtime success for the present branch or for F11 additions.

An exact scan of upstream generated TConstruct recipe JSON found 20 `tconstruct:no_container` occurrences: six tool-modifier recipes, four device crafting recipes and ten melting recipes (Copper Can, Casting Tank, and seared/scorched tanks, gauges and lanterns). One `tconstruct:block_tag` occurrence is the basin water-to-mud recipe (`minecraft:convertable_to_mud`, 250 mB water, 47 ticks). This is core bundled data, not merely third-party datapack compatibility. The melting `Ingredient::parse` currently rejects both types; unsupported cases are not silently matched. The device-crafting paths have their own narrower empty-gauge checks and must be checked separately from melting and modifier matching.

The formal host `horizon-items/src/items.rs` `ItemInfo::block` supplies an item-to-block-state association. The block-tag matcher should derive each registered item's block identity from that association and the resolved block tags; it must not assume item and block IDs are identical or accept an item without a block. The stack-aware no-container matcher needs source `hasCraftingRemainingItem()` behavior, including static item remainders and the actual portable-tank/can data: no item-only check should treat filled or malformed containers as empty. The matching Melter, Foundry and GUI lookup paths must use the same result, and condition order, fluid conservation, save/reload and LAN require dedicated verification. These handlers remain unimplemented here.
