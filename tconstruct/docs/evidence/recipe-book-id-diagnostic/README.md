The disposable creative world used the overlay-only fixture documented in `../overlay-recipe/` and two synthetic probe recipes, all explicitly unlocked. `recipe-book-packet-view.log` records the actual received packet and mapping of the same remote client's displayed IDs before and after the craftable filter. The packet's ID 1422 carries the two-plank Stick recipe, whereas the client's local Book maps 1422 to `minecraft:stick_from_bamboo_item`. Packet ID 976 is the synthetic added `minecraft` recipe and the client maps it to `minecraft:nether_brick`, a furnace-category recipe. IDs 1747, 1748 and 1749 (the added TConstruct probe and workstation recipes) have no corresponding entries in the client's local Book. The view contains the crafting table and the mismatched bamboo Stick only; with filtering on it contains none. The earlier local `level.recipe_book` set was not the remote server's authority and must not be interpreted as its unlock state.

The fixed host's `remote_recipe_book_add` retains packet IDs but does not consume the accompanying `RecipeDisplay`, category, or requirements. `ensure_book` instead builds entries and display IDs from the window's local recipe/index tables. Server datapack changes can therefore make the numeric spaces diverge; this is broader than TConstruct and also affects normal Minecraft datapacks. A complete general fix must build the remote book from server entries (or otherwise synchronize recipe data and its display numbering), handle packet replace/removal, tags/filtering, reload, ghost and placement by server display ID, and test local integrated-server plus LAN. Display-only icon substitution is insufficient, since a wrong entry can be clickable. This diagnostic does not implement a fix and does not test all packet shapes or versions.
