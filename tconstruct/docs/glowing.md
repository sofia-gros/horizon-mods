# Glowing ability (in progress)

Glowing's source recipe uses glowstone, a daylight detector and shroomlight, consumes one ability slot and permits one level. It applies to the source interactable-or-boots durability tag. Source: TConstruct `f4e77d43f39ba1047bf93ae816b7e1beaab514c2`, `ModifierRecipeProvider` and `ModifierProvider`.

The source light is `tconstruct:glow`, emits level 14, has no collision or drops, and attaches to a full solid face. A placement uses the clicked face first, then tries other supporting faces; liquid and existing glow are rejected. A surviving glow is removed when its support disappears. A successful direct placement costs five durability with cause `tconstruct:glowing`; broken tools do not place it. The source also has boot walking in low block light and projectile hit placement, with its own launch/hit wear rules. The original glow texture, model and directional blockstate are included from that pinned revision. A six-direction light-level-14 block is declared and resource preparation assigns empty collision. The support-face lookup, an update queue, source selection outline and direct right-click path are connected. Recipe and ability-slot handling use the original recipe, including Crystal reapplication. The registration and hooks have not been formally built or tested in game. Boots walking is connected to the existing local/LAN location-change path with the source radius and light conditions, but has not been built or game-tested. Left-click interaction remains unimplemented. Live arrows carry the firing-tool snapshot, charge the primary launch, and attempt a glow on a block or mob hit; they have not been built or tested in game. Saved-arrow reload, rockets, fishing hooks and player-hit paths remain unimplemented.

The shared placement selector implements the preferred face, source fallback direction order, support checks and rejection conditions. Four lightweight tests cover selection, invalid destinations and walking geometry; the world and interaction hookups remain unverified.

The durability hook has a scoped modifier-cause path, so Glowing actions can pass their actual cause through Tanned, Overslime, Unbreakable, Dense and Reinforced. The existing ordinary-wear callers still pass no cause. Limited Mixins plan and lightweight formula tests passed; no full transformation, build, game or LAN validation has been done. Direct use passes the Glowing cause on a successful placement; it has not been validated in game. The remaining source actions are required before this ability can be considered complete.

The pinned Mixins plan rejects a projectile struct extension (`E_STATE`: all fields are public). Both a return hook on `horizon_client::entity_nbt::arrow_from_nbt` and an operation hook at its `Game::spawn_loaded_entities` call report `E_UNSUPPORTED_CONTROL_FLOW` because of unsupported `?` or closure contexts. Consequently Glowing on an in-flight arrow is not retained across save/reload; no ammunition component or vanilla item data is repurposed.
