# Fluid modifier implementation boundaries

Scope: TConstruct's six bundled `no_container` modifier recipes only; weapon/armor material modifiers assigned to other developers are not changed. Pinned source is `f4e77d43f39ba1047bf93ae816b7e1beaab514c2`. These are not implemented by #224: matching their ingredients is insufficient to apply their effects.

| Modifier | Source effect and trigger | Unconnected product path |
| --- | --- | --- |
| `tconstruct:tank` | `ModifierProvider` adds 1,000 mB capacity per level and `tank_handler`; recipe costs one upgrade slot. | Station upgrade whitelist, tool stat rebuild, persistent tool tank and its transfer/UI path. |
| `tconstruct:slurping` | `SlurpingModule` applies the selected fluid's entity effects to its holder after a 21-tick use, consuming the recipe's actual fluid amount; adds 1,000 mB per level. | Use duration and completion for held/armor interaction; fluid-effect lookup/application, tool data commit and item/LAN synchronization. |
| `tconstruct:spilling` | `SpillingModule` applies fluid effects after a fully charged successful melee hit or a successful launcher hit, consuming the recipe amount; adds 1,000 mB per level. | Post-hit and projectile context, effect execution, authoritative held-tool mutation and sync. |
| `tconstruct:splashing` | `SplashingModule` applies fluid effects through entity/block interaction, including nearby targets and per-target consumption with interaction cooldown; adds 1,000 mB per level. | Interaction routing, area selection, effect execution, cooldown and atomic tool mutation. |
| `tconstruct:bursting` | On direct incoming damage from another entity, `UseFluidOnHitModifier` has a 25% chance per effective level to apply the effect to the attacker; adds 1,000 mB per level. | Incoming-hit context and equipment slot ownership, source random ordering, effect application and saved equipment synchronization. |
| `tconstruct:wetting` | On eligible incoming damage not bypassing effects/invulnerability or self-caused, the same chance applies the effect to the wearer; adds 1,000 mB per level. | Damage tags and attacker context, source random ordering, effect execution and equipment synchronization. |

The five ability recipes each cost an ability slot. All six also install the source `tank_handler`. `ToolTankHelper` stores the fluid under `tic_persistent` / `tconstruct:tank_fluid` as a Forge fluid stack and derives capacity from `tconstruct:tank_capacity`; it preserves fluid metadata and clamps writes to capacity. The existing `source-fluid-container.rs` and `source-smeltery-tank.rs` implement container transactions, but they operate on machine tanks and do not currently expose a modifier-bearing tool's persistent tank or synchronize it with the source tool capability. `source-upgrade-rules.rs` has a whitelist of supported upgrade effects, so the six recipe outputs remain rejected. #224 connects the stack-aware ingredient check only; it does not enable those modifiers.

A coherent implementation must add source-compatible tool capacity and persistent fluid state, preserve metadata and other item data, connect at least one usable transfer path and atomic tool write, and only then admit the corresponding recipe. Slurping, spilling, splashing, bursting and wetting additionally require the applicable source fluid-effect lookup and hook; the cannon needs related effect machinery but has separate projectile requirements. Do not add recipe outputs without their effect. Test conflicting fluids, zero/full capacity, malformed tags, modifier removal, full output, per-effect consumption, creative resource rules, equipped/held state, break/save/reload and LAN using exact candidate heads.
