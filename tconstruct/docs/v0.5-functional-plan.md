# v0.5 functional plan (2026-11-02 snapshot)

> Historical planning snapshot: status, role assignments, host versions and PR states below describe the 2026-11-02 baseline, not current results or operating instructions. Verify current main, exact PR heads and recorded evidence before using this register.

**Scope decision:** standalone playable prerelease, not the complete port. Required: the original core material → part → tool/weapon/armor → use/repair/modification, workstation → melting/alloy/casting, natural acquisition and in-game guide loops. Applicable source data, including unimplemented operations, remains required. An integration branch whose original condition is false in the standalone configuration is outside that configuration; evaluate its actual condition rather than assuming an ID is external. No new smartphone port or independent end-to-end survival run is a release gate: the user owns the survival playthrough. Linux launch and existing Windows delivery commitments are tracked separately; never claim Windows tested without evidence.

## Standalone exclusions

Two exclusion rules, not a fixed count of source records: (X1) integration-only branches whose actual config/mod/tag condition is false in standalone; conditional material candidates are listed in the execution plan and must be evaluated individually, not automatically excluded; (X2) `the_one_probe` integration when that external mod is absent. If a condition is true, the operation is required under its owning task. Mobile native support and independent full survival playthrough are not added as gates; they are not assertions of implementation completion.

## Seven release validation gates

V1 latest official target pair, exact SHA, official plan/apply/build and both separate packages; V2 F03/F04/F13 workstation atomic transactions and source components; V3 F02/F05/F06/F12 gameplay, stats/traits and bounded broken behavior; V4 F07–F11 machine/recipe fluids, data and conservation; V5 F14–F16 world/loot/guide/progression representative source-backed cases; V6 persistence, local and representative LAN, vanilla regressions and Linux installation; V7 documentation/artifact provenance, existing Windows commitment and exact test limitations, plus user-owned survival instructions. A failed or untested LAN path is documented and isolated from safe SP; release claims must match actual tests. Each gate records exact integrated tree, artifact, mode, fixture, observed result and unresolved exceptions. V7 Windows installation verification: the test role T runs the documented Windows installation and launch on an available Windows environment using the exact release artifacts and records environment, artifact SHA, commands, result and screenshot/log. Until actually exercised, the Windows check is pending and V7 is not passed. If no Windows environment is available, report the blocker to the parent without claiming a pass. The user-owned survival playthrough has a separate user-validation record (not started / in progress / feedback received); it is not a T-run gate and is never fabricated by T.

v0.5 is complete under this proposal when **all 20 required F units** are complete on main, all **seven applicable gates** pass with their exact evidence, and only individual operations with evidence that no safe current official path is available remain explicitly held, including the historical operations if still applicable. Source catalogs are audit inputs; completing an ID scan without its owning task's behavior and tests does not close it. No predicted date or percentage is implied. Parent presents the plan first, then distributes task numbers without waiting for a further reply.
