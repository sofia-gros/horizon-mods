# Four default-name lifetime cases: preparation only

This independent preparer consumes the four unchanged Rust cases published at
`62f050a1c4eab72da11032f4d6f059323c7e1e8a`. It does not change their expectations,
install a default-name owner, materialize components, create a language dictionary,
or modify the item-name-removal codec32 group. No workflow or trigger is added.
Native preparation, metadata, Rust compilation and execution are **unrun**.

The dependency family follows the successful actual items/core/world display
fixture: real official path dependencies and `serde_json`, not a replacement
Horizon or an independently shipped library. The generated Cargo package is only
an ephemeral test harness. Official Horizon is fixed at
`624c4f6265c02296fbe8a80f029dd0d987fb94c0`; the official lock is copied unchanged
before an explicitly separate offline metadata step adapts only that copy.
The helper permits no identity outside the official lock except this one harness.
All four native core/client-core/items/world package identities and actual paths
must be unique. No registry substitution, test-support feature or custom patch is
introduced. The larger host's graphics patches are not imported into this small
dependency graph; if resolution requires an unapproved identity it fails rather
than fetching a replacement or relaxing the lock check.

Preparation reads a clean official Git checkout, including ignored/untracked
status, verifies pinned native inputs, and seals regular file bytes/modes,
directory presence/kind and symlink targets without following links. Directory
permission bits are not sealed. Mod source groups have exact file sets and no
symlinks. Generated input is limited to unchanged `lib.rs`, `Cargo.toml`, copied
`Cargo.lock` and a receipt. Unexpected files, empty directories or links fail.
Before and after metadata, official/Mod/input identities are rechecked; only the
copied lock may change. A failed resolution remains unresolved, not repaired by
guessing or silently retrying. The receipt is evidence for an outer runner, not a
standalone execution or authorisation token.

Future execution must be granted and orchestrated separately: use cold official
fetch/locked dependency seeding, then offline metadata, locked compile, actual
compiler evidence and one sealed-binary execution of exactly the four named cases
with zero failures/ignored/filtered. Keep targets outside the sealed source trees.
Use the existing remote runner's filesystem floor/reserve, bounded process groups,
source/lock/OUT_DIR/executable seals and final cleanup even on failure. This helper
also bounds its own Git/metadata child group to 60 seconds plus teardown. There is
no local native run authorised by merely preparing or publishing these files.

The tests cover the existing shared Weak-cache lifetime, holding/releasing the
same-root snapshot across a file change, copying custom metadata into Items, and
non-mutating explicit-name reads. A pass would document that existing behaviour,
not prove Items-owned default payload population, content item generation, all
reload scheduling, real Game rendering, network delivery or production connection.
The proposal and limitations remain in the original lifetime group's README.
