This fixture is source-only and unrun. It is a follow-up to the private bridge
at709a2b9456cbbed876240fb6de9a93d2f6d6543f, not an activated transport or a passed
Game test. Six pure extraction/source checks pass. No Cargo manifest, lock,
metadata, Rust compiler or native execution has been invoked for this fixture.

The planned crate imports actual horizon_client_core Text and actual
pluto_inventory_api Payload. It does not replace either with a model. The
horizon_client alias only exposes the exact Text reexport required by the
unchanged consumer wire file; it is not an installed-client composition proof.
Before execution, a separate reviewed preparer must pin official41f, locks,
whole API input set, dependency identities and actual compiler/artifact outputs.

render_wire.py takes exact pinned bytes and returns seven source files in memory.
It retains the complete original wire/BookId files. It extracts the old response
only from decode_reply through clamp and assignment, adapting the byte parameter,
module path and early-return spelling with a full inverse check. The current-Game
sequence/View acquisition and old cancellable packet wrapper are outside this
fixture. It copies the actual new consumer update, widening only fixture function
visibility, and copies RetainedView plus its implementation without changing a
byte. One fixture-only constructor supplies already-acquired pages/page values.
No fake Game, observer, registry, opening or socket is constructed.

Ten new cases compare the old and proposed helpers on actual Text spans and
retained component values: all six legacy titles; cover/clamp; repeated same
sequence; wrong sequence/book; malformed/short/empty/oversized bodies; invalid
current roots/titles; exact262144-byte body plus8-byte header; legacy metadata
filtering; an externally supplied matching value; and bad-then-good same-sequence
replies. Maximum-size and subsequent-response acceptance are asserted explicitly.
The complete planned inventory is21: these10 plus the unchanged wire6/BookId5.
Only the new10 are selected in this proposed gate; no existing test is removed
or described as rerun by source inspection.

These tests do not demonstrate that a real overlay retains a book, that a remote
bootstrap executes, that Game borrowing compiles, or that a packet reaches the
one native observer. They deliberately do not synthesize an owned token or use
input eligibility as retained-view authority. Native type/registry6, complete
plan/guard order, whole-package composition, real Client/LAN and translation
refresh are separate requirements. The ordinary listener and protocol remain
unchanged until those integration gates are reviewed.
