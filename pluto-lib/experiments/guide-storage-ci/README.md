# Isolated official Guide storage typing

Source preparation only. This workflow is not an installed Pluto feature or a
translation/LAN repair. It tests one prerequisite: whether the excluded proposed
`RetainedBook<books::BookScreen>` field and the eleven exact official source changes
typecheck in the actual Horizon gameplay library and binary.

The copied seven prototype inputs are byte-identical to local c7a89ec5 / published
b434e9a4. `inputs.json` also pins the shared CI guard and portable Git exporter.
No ordinary manifest, runtime adapter, TConstruct handler or package guard changes.
The prototype remains under experiments, outside the package's fixed mixins/API
roots. The normal official checkout is never patched, and no engine fork is read.

## Intended, separately authorized gates

1. Exact public WIP branch, read-only permissions, standard runner, no cache,
   artifact publication, manual input or release. First preserve source on a
   non-trigger branch; independent review and coordinator release are required
   before creating `checkpoint/guide-storage-type-ci-20261106`.
2. Run fourteen bounded Python runner checks. These model parser/guard failures;
   they are not actual Game tests.
3. Under the continuous 10 GiB + 128 MiB floor (and initial additional 2 GiB
   reserve), install the official pinned Rust toolchain and usual host headers.
   Fetch only official Horizon 624c4f62, verify the exact commit/lock and preserve
   the complete original checkout and exported pristine file sets.
4. Run the existing seven prototype source/hunk tests against that pristine
   source. Regenerate the exact frozen patch in memory; refuse any source,
   inventory, hunk or output difference. Copy only to a fresh runner-owned
   experiment, then change exactly ten existing files plus retained_book.rs.
   The BookScreen enum itself, Cargo manifests and Cargo.lock stay unchanged.
5. Fetch the official locked dependency set. Compare full locked/offline metadata
   with no default features for pristine and experiment after normalizing only
   their root paths. Local package/target sources must remain within their tree.
   No previous Pluto/v15 build cache or dependency identity is assumed.
6. Check actual horizon-client lib and named bin with no default features,
   one job, debug/incremental disabled, locked/offline dependencies. Require
   actual rustc invocations for client_lib.rs and gameplay src/lib.rs/src/main.rs.
   There is no server/mock fixture or extracted Game substitute.
7. Recheck complete source/lock/file-set and build-script output seals. Missing,
   failed or unverified gates cannot emit a successful final receipt. All child
   process groups, including residual children, have bounded termination.

The verbose compiler log remains on the ephemeral runner and is hash-bound.
The console contains phase results, hashes, required compiler identities/hashes,
and a compact final receipt. On failure only a bounded diagnostic tail is shown;
the full raw log is not published. This avoids the previously observed oversized
Actions log transport failure without pretending that hidden logs were retrieved.

## What a pass would not establish

- This is a proposed official host extension, **not a Mixins-only solution**.
- It does not install the prototype in ordinary Pluto or prove composition with
  the full current TConstruct bundle or arbitrary third-party field access.
- An observed storage stamp is not an owned opening or reply authority. No
  acquisition, conditional update, mutating observer or new packet is introduced.
- Client/window lifecycle, retained overlay refresh, identical reopen, language
  selection/reload, late/duplicate replies and real LAN behavior remain untested.
- The legacy 262,152-byte reply envelope and old decoder contract remain separate
  from Pluto's smaller read-only observer cap. Existing LAN behavior is preserved.

The earlier Guide identity 10 tests prove only pure consumer mappings/anchors.
The bounded language22 run has a complete receipt. Installed language-host CI
has workflow/job success, but its final oversized raw log was not independently
recovered; its fourteen test names and final seals must not be inferred from the
bounded result. See published status closure 07a7168c for that distinction.
