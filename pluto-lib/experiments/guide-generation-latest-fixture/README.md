# Latest native Font generation fixture preparer

Source-only preparation for unchanged `d1941c77` generation delegation and six
actual native Font tests. It does not invoke Git, Cargo, Rust, Mixins, network,
Game or a renderer. No workflow/runner is added by this slice. Source-only tests
of this preparer are not a real official fixture, native compilation or success.

The previous Font12 proof at `49a2401e` used older 624c native sources. Those 12
original test bodies remain byte-identical but are only compiled by this proposed
new harness. The new six-case generation filter is separate, with 21 compiled
names total and 15 filtered. Actual inventory must match before test execution.
The three other names are production converter unit tests, also not executed by
the six-case filter. Full GPU drawing, visible 17-line UI, Game ownership, title
identity, translation refresh and existing LAN are outside this fixture.

The proposed controller must fetch only official Horizon at exact f4dcf8a2 with
its fixed lock, check clean Git identity and full file/mode/link seals, cold-fetch
locked dependencies, and then prepare a fresh owned output directory. This
preparer verifies selected native source/manifest hashes and copies the exact
29-file public API, helpers, consumer and both original Rust fixture inputs.
It preserves their relative include paths and original synthetic bitmap/metric
provider. It does not borrow an old or unverified Minecraft resource tree.

Cargo resolution must run as a separate guarded outer-controller phase, with
strict JSON stdout separate from stderr. Only the fixture lock may adapt, and
its package identities must stay within the official lock plus the two exact
local fixture/API packages. Path dependencies must belong to the fresh official
checkout or exact fixture/API paths. All three official path patches are carried
without changing versions or features. No nested process group exists here.

Before compilation, the controller must record full fixture source/lock seals,
then require fresh actual native core/render and fixture compiler witnesses.
After compilation it must seal the binary and generated OUT_DIR sources and run
only the sealed executable: exact 21-name list, then six named generation tests
with zero failures/ignored and 15 filtered. Recheck all native/Mod/fixture/lock/
output/binary seals afterward, including failure paths. Follow the unchanged
10 GiB + 128 MiB floor, setup reserve, bounded PGID termination and compact false
receipt policy. This preparer alone cannot establish those controller gates.

`prepare()` performs atomic creation and rejects preexisting outputs. The outer
controller owns the fresh parent and its filesystem; concurrent hostile writers
are not an accepted condition. The functions have no independent source-revision
or process-authorization authority. All native execution awaits a separately
reviewed dedicated runner and serial release. Ordinary manifests and LAN remain
unchanged.

The first shallow `/tmp` draft import stopped because the repository-relative
parent depth did not exist. It was moved into the intended repository-shaped
source directory, without changing runtime code. Fourteen pure structural tests
then passed. A final source/hash test is also included for the actual frozen

## Explicit single-root workspace correction

The first actual run at `a4ebdab1` prepared the fixture and completed offline
metadata, but rejected workspace membership before Rust compilation. The raw
member set is unavailable; the false result is preserved separately. The
[Cargo workspace contract](https://doc.rust-lang.org/cargo/reference/workspaces.html#the-members-and-exclude-fields)
automatically includes in-tree path dependencies unless excluded. The generated
manifest now explicitly excludes `inventory-api` from workspace membership and
sets `default-members = ["."]`. It remains the exact same path dependency, with
unchanged features, manifest bytes, lock-identity restrictions and source copies.
The root package remains the only test package. No extra workspace member is
accepted to bypass the old rejection.

Metadata must now report exactly the fixture ID as its sole member and default
member, with the exact fixture workspace root. Unknown, duplicate, missing, API
or redirected members/defaults/roots are rejected. Three additional pure tests
bring this preparer to eighteen checks; they model metadata, not actual Cargo
resolution. The corrected generated manifest awaits a separately reviewed run.
The controller prints bounded member/default-member IDs, names, manifest paths
and root before admission, with counts/truncation flags. That diagnostic does not
change the full strict checks or the complete metadata byte/hash receipt.
