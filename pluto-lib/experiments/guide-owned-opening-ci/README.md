# Queued isolated ownership check

Source-only controller for exact `guide-owned-opening` source `dc2bc59f`.
Publishing this controller on its source branch does not run it. The dedicated
trigger must be created only after independent review and coordinator release.
No local Rust, Cargo, metadata, host copy or native execution is authorized here.

The controller reuses the unchanged `guide-storage-ci` process/disk/log/metadata
utilities and old eleven-file generator. It runs its ten parser/scope checks plus
the prior fifteen, then the exact source-only integrity check. One std-only rustc
compile lists all seventeen tests; a separate process runs only the ten exact
ownership tests (seven original storage cases filtered). Binary/source seals
remain fixed. That group uses generic Rust values, not a mock presented as Game.

Only after those gates pass does it fetch/export exact official `624c4f62` and
apply the original proposed storage patch to a private copy. It appends the two
pinned owned-opening and real BookScreen fragments to the same helper. The other
ten changed host files remain byte-identical to the original experiment. Full
locked/offline metadata must match after source-root normalization. Actual
client-lib, gameplay lib and binary compiler invocations are required; a Fresh
line or the std fixture alone cannot stand in for that gate.

The public exact-branch/read-only/fixed-runner contract, continuous filesystem
floor with initial 2 GiB reserve, bounded PGID teardown, separate metadata stdout,
compact logs and failure receipt are reused. No apt/sudo, caches, artifacts,
settings/permission changes, Mixins install or additional CI are introduced.
Verbose native logs remain ephemeral and hash-bound; compact receipt records
actual invocations and all final source/build-output seals.

Even success proves **only** generic storage mechanics and isolated native
typing. It does not prove permission to open a Game window, ordinary Pluto/main
composition, catalog-generation stability, language rebuilds, authoritative reply
consumption, actual Client/overlays or LAN. Production and old LAN are unchanged.
