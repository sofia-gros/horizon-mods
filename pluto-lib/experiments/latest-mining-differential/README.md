# Pending mining differential fixture

This is source preparation only. Rust, Cargo metadata and the actual native adapter have not been compiled or executed here. This fixture is separate from the successful Template6/default4 run and from the ordinary package.

`regression_tests.rs` contains twelve additional named cases. A later fixture must use actual latest f4dc Horizon items/world, not semantic stubs. `prepare_sources.py` is a pure bytes-map renderer: it checks the full exact input set, copies unchanged main08afa rules/math and the same packaged Pluto Tool rules, and extracts the unchanged Dwarven boost function. It runs no command and writes no output. Native lock/path/dependency identity remains the responsibility of the future bounded controller.

The native scalar division is copied exactly from the source-pinned hand.rs. The tick and delayed functions are explicitly predicate projections, not native Game implementations: the first checks only the numeric threshold, the second maps the guard/done.is_some decision to a boolean. They prove no actor swap, permissions, packet, block destruction or effect execution. Their purpose is to prevent a false cross-caller NaN equivalence claim.

## Additional cases

1. Incoming current speed remains the base instead of recomputing Tool speed.
2. Native attributes do not multiply the independent source flat addition.
3. Haste/Conduit max, every fatigue branch, water/Aqua Affinity and ground arithmetic retain their order.
4. Current eye-water and previous-eye Hydraulic are independently supplied.
5. Flat addition precedes Airborne, then Armor Haste.
6. Broken flag/durability suppress tool effects while retaining the independent armor stage.
7. Malformed Tool versus known ineffective Tool stays distinct.
8. Unavailable Broad versus known-empty membership stays distinct.
9. Queried target height affects Dwarven without a mining-position cache.
10. Native hardness/harvest division is preserved.
11. Zero hardness/zero speed remains NaN and has different tick versus delayed caller decisions.
12. The official division fragment does not clamp negative/non-finite speeds.

That last statement is limited to the official arithmetic fragment and the absence of a new clamp in the adapter. The unchanged TConstruct conditional-speed policy already ends with `speed.max(0.0)`; it remains present and is not overridden or described as preserving every non-finite/negative policy input.

The whole unchanged source modules also contain their existing tests. A future runner must enumerate the full generated binary and separately require all twelve new names; it must not silently filter the old tests or call twelve the total suite count.
