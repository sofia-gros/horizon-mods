with the central grouped integration. The feature package is smaller than the
current central foundation and its old proof must not be substituted for the
new combined package. No production TConstruct consumer is activated.

Exact native Input and real Items/ItemStack/codecs are used. Inherited fixture
special endpoints and wrappers are modeled and do not establish automatic
assembly, Menu consumption, game runtime or LAN behavior. The source assertions
about official Menu/crafter order are static evidence explaining why automatic
pair integration is deferred, not execution of those paths.

The pair is an owned staged proposal with explicit input-value revalidation,
not a live slot/world token or an inventory transaction. The codec validation
is an item-to-Tag/item-from-Tag check, not arbitrary binary serialization or
network transport. See `crafting-products.md` for the exact contract and
remaining authoritative-consumption blocker.
